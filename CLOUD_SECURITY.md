# Cloud Security & IAM Setup Guide

This guide details the security baseline, IAM role requirements, and manual/automated configuration procedures for the **Real-Time Cybersecurity AI & ADK Platform** on Google Cloud Platform.

---

## 🛡️ Architecture & Security Model

The security model operates on the principle of **least privilege**:
1. **Human Administrator / User Account:** Needs broad administrative roles across BigQuery, Vertex AI, GCS, IAM, and Pub/Sub to provision and configure project resources.
2. **BigQuery Remote Connection SA:** A platform-managed service account generated by BigQuery to securely access external object tables (desktop screenshots in GCS) and query Vertex AI foundation models.
3. **Orchestrator Service Account (`bq-continuous-query-sa`):** A dedicated runtime service account that executes BigQuery continuous queries, publishes to Pub/Sub, interacts with ADK agents, and signs temporary GCS URLs.

## 1. Required Google Cloud APIs

Ensure the following 7 core APIs are enabled in your target project:

| API Service Name | Identifier | Purpose |
|---|---|---|
| **BigQuery Unified API** | `bigqueryunified.googleapis.com` | High-throughput query processing and continuous queries |
| **BigQuery Connection API** | `bigqueryconnection.googleapis.com` | Remote connections to Vertex AI and Cloud Storage |
| **Vertex AI API** | `aiplatform.googleapis.com` | Gemini model endpoints and Agent Runtime |
| **Cloud Pub/Sub API** | `pubsub.googleapis.com` | Streaming event bus for raw logs and continuous alerts |
| **IAM Service Account Credentials API** | `iamcredentials.googleapis.com` | Generation of short-lived tokens and V4 signed URLs |
| **Cloud Resource Manager API** | `cloudresourcemanager.googleapis.com` | Managing IAM policy bindings and metadata |
| **Google Cloud Storage JSON API** | `storage.googleapis.com` | Storing screenshots, raw logs, and escalation files |

### Enable via CLI:
```bash
gcloud services enable \
    bigqueryunified.googleapis.com \
    bigqueryconnection.googleapis.com \
    aiplatform.googleapis.com \
    pubsub.googleapis.com \
    iamcredentials.googleapis.com \
    cloudresourcemanager.googleapis.com \
    storage.googleapis.com \
    --project="${PROJECT_ID}"
```

### Enable via Cloud Console:
1. In Cloud Console, open **APIs & Services** > **Library**.
2. Search for each API name above and click **Enable**.

## 2. User Account IAM Permissions

Your personal or administrator Google user account requires the following **13 IAM roles**:

| Role Name | IAM Role ID | Purpose |
|---|---|---|
| **BigQuery Data Editor** | `roles/bigquery.dataEditor` | Create, modify, and delete BigQuery datasets and tables |
| **BigQuery Connection Admin** | `roles/bigquery.connectionAdmin` | Create and manage external remote connections |
| **BigQuery Resource Editor** | `roles/bigquery.resourceEditor` | Create reservations and slot assignments |
| **BigQuery User** | `roles/bigquery.user` | Run queries and execute jobs |
| **Colab Enterprise User** | `roles/colab.user` | Run Colab Enterprise notebooks |
| **Notebook Runtime User** | `roles/aiplatform.notebookRuntimeUser` | Manage notebook execution runtimes |
| **Storage Admin** | `roles/storage.admin` | Create GCS buckets, upload logs, and manage objects |
| **Service Account Admin** | `roles/iam.serviceAccountAdmin` | Create and manage service accounts |
| **Service Account User** | `roles/iam.serviceAccountUser` | Attach service accounts to pipelines and runtimes |
| **Service Account Token Creator** | `roles/iam.serviceAccountTokenCreator` | Impersonate service accounts to create short-lived credentials |
| **Project IAM Admin** | `roles/resourcemanager.projectIamAdmin` | Assign IAM roles to service accounts and members |
| **Pub/Sub Editor** | `roles/pubsub.editor` | Create and configure Pub/Sub topics and subscriptions |
| **Vertex AI Administrator** | `roles/aiplatform.admin` | Deploy agents, configure Agent Runtime, and manage models |

### Grant User Roles via CLI:
```bash
USER_ROLES=(
  "roles/bigquery.dataEditor"
  "roles/bigquery.connectionAdmin"
  "roles/bigquery.resourceEditor"
  "roles/bigquery.user"
  "roles/colab.user"
  "roles/aiplatform.notebookRuntimeUser"
  "roles/storage.admin"
  "roles/iam.serviceAccountAdmin"
  "roles/iam.serviceAccountUser"
  "roles/iam.serviceAccountTokenCreator"
  "roles/resourcemanager.projectIamAdmin"
  "roles/pubsub.editor"
  "roles/aiplatform.admin"
)

for role in "${USER_ROLES[@]}"; do
  echo "Granting $role to ${USER_EMAIL}..."
  gcloud projects add-iam-policy-binding "${PROJECT_ID}" \
    --member="user:${USER_EMAIL}" \
    --role="$role" \
    --condition=None
done
```

## 3. BigQuery Remote Connection (`continuous-query-vertex-ai-connection`)

BigQuery requires an external Cloud Resource connection to query object tables and invoke remote Vertex AI models.

### Manual Procedure (Cloud Console):
1. Navigate to **BigQuery Studio** in the Google Cloud Console.
2. In the Explorer pane, click **+ ADD** > **Connections to external data sources**.
3. Configure the connection dialog:
   * **Connection type:** `Vertex AI remote models, remote functions and BigLake (Cloud Resource)`
   * **Connection ID:** `continuous-query-vertex-ai-connection`
   * **Location type:** Multi-region `US` (or matching region)
4. Click **Create connection**.
5. In the Explorer tree, locate **External Connections** > click `continuous-query-vertex-ai-connection`.
6. In the **Connection info** pane on the right, copy the generated **Service account ID** (e.g., `bqcx-123456789-abcd@gcp-sa-bigquery-condel.iam.gserviceaccount.com`).
7. Open **IAM & Admin** > **IAM**.
8. Click **Grant Access** (or edit permissions) and paste the copied Service Account ID as the Principal:
   * Assign role: **Vertex AI User** (`roles/aiplatform.user`)
   * Assign role: **Storage Object Viewer** (`roles/storage.objectViewer`)
9. Click **Save**.

### CLI Equivalent:
```bash
# 1. Create connection
bq mk --connection \
    --location="${BQ_LOCATION}" \
    --project_id="${PROJECT_ID}" \
    --connection_type=CLOUD_RESOURCE \
    continuous-query-vertex-ai-connection

# 2. Extract generated Service Account ID
CONNECTION_SA=$(bq show --connection "${PROJECT_ID}.${BQ_LOCATION}.continuous-query-vertex-ai-connection" \
    --format=json | jq -r '.cloudResource.serviceAccountId')
echo "Connection Service Account: ${CONNECTION_SA}"

# 3. Grant IAM permissions to the Connection SA
gcloud projects add-iam-policy-binding "${PROJECT_ID}" \
    --member="serviceAccount:${CONNECTION_SA}" \
    --role="roles/aiplatform.user"

gcloud projects add-iam-policy-binding "${PROJECT_ID}" \
    --member="serviceAccount:${CONNECTION_SA}" \
    --role="roles/storage.objectViewer"
```

## 4. Orchestrator Service Account (`bq-continuous-query-sa`)

A dedicated service account named `bq-continuous-query-sa` is used to orchestrate continuous queries, publish alerts to Pub/Sub, perform ADK actions, and write to GCS.

### Required Roles:
1. **BigQuery Connection User** (`roles/bigquery.connectionUser`)
2. **BigQuery Data Editor** (`roles/bigquery.dataEditor`)
3. **BigQuery Data Viewer** (`roles/bigquery.dataViewer`)
4. **BigQuery User** (`roles/bigquery.user`)
5. **Logs Writer** (`roles/logging.logWriter`)
6. **Pub/Sub Publisher** (`roles/pubsub.publisher`)
7. **Pub/Sub Viewer** (`roles/pubsub.viewer`)
8. **Service Account Token Creator** (`roles/iam.serviceAccountTokenCreator`)
9. **Service Usage Consumer** (`roles/serviceusage.serviceUsageConsumer`)
10. **Storage Object User** (`roles/storage.objectUser`)
11. **Vertex AI User** (`roles/aiplatform.user`)

### Manual Procedure (Cloud Console):
1. Navigate to **IAM & Admin** > **Service Accounts**.
2. Click **+ CREATE SERVICE ACCOUNT**.
   * **Service account name:** `bq-continuous-query-sa`
   * **Service account ID:** `bq-continuous-query-sa`
   * **Description:** `Runs BigQuery continuous queries, Pub/Sub, and ADK operations.`
3. Click **Create and Continue**.
4. In the **Grant this service account access to project** step, add all 11 roles listed above.
5. Click **Done**.
6. Find `bq-continuous-query-sa` in the list, click on it, and select the **Permissions** tab.
7. Click **Grant Access**:
   * **New principals:** `bq-continuous-query-sa@${PROJECT_ID}.iam.gserviceaccount.com` (self)
   * **Role:** `Service Account Token Creator` (`roles/iam.serviceAccountTokenCreator`)
   * *Why:* This allows the service account to sign V4 GCS screenshot URLs keylessly without requiring downloadable JSON service account keys.

### CLI Equivalent:
```bash
# 1. Create the Service Account
gcloud iam service-accounts create bq-continuous-query-sa \
    --project="${PROJECT_ID}" \
    --display-name="Cymbal Cyber Orchestrator SA" \
    --description="Runs BigQuery continuous queries, Pub/Sub transformations, and ADK operations"

SA_EMAIL="bq-continuous-query-sa@${PROJECT_ID}.iam.gserviceaccount.com"

# 2. Grant project-level roles
SA_ROLES=(
  "roles/bigquery.connectionUser"
  "roles/bigquery.dataEditor"
  "roles/bigquery.dataViewer"
  "roles/bigquery.user"
  "roles/logging.logWriter"
  "roles/pubsub.publisher"
  "roles/pubsub.viewer"
  "roles/iam.serviceAccountTokenCreator"
  "roles/serviceusage.serviceUsageConsumer"
  "roles/storage.objectUser"
  "roles/aiplatform.user"
)

for role in "${SA_ROLES[@]}"; do
  echo "Granting $role to ${SA_EMAIL}..."
  gcloud projects add-iam-policy-binding "${PROJECT_ID}" \
    --member="serviceAccount:${SA_EMAIL}" \
    --role="$role" \
    --condition=None
done

# 3. Grant self-impersonation for keyless V4 signed URL generation
gcloud iam service-accounts add-iam-policy-binding "${SA_EMAIL}" \
    --project="${PROJECT_ID}" \
    --member="serviceAccount:${SA_EMAIL}" \
    --role="roles/iam.serviceAccountTokenCreator"
```

## 5. Automated Setup via Terraform

The entire infrastructure outlined above (APIs, Remote Connection, Service Accounts, Role Bindings, BigQuery Tables, Pub/Sub, and GCS buckets) is pre-codified in `src/demo/terraform/`:

* **APIs:** `src/demo/terraform/main.tf`
* **Remote Connection & Permissions:** `src/demo/terraform/bigquery.tf`
* **Service Account & Roles:** `src/demo/terraform/iam.tf`

### Run Terraform:
```bash
cd src/demo/terraform

# 1. Initialize modules and providers
terraform init

# 2. Preview resources to be created
terraform plan -var="project_id=${PROJECT_ID}"

# 3. Apply changes to Google Cloud
terraform apply -var="project_id=${PROJECT_ID}" -auto-approve
```

## 6. Verification Checklist

Run these commands to confirm your cloud security setup is healthy:

```bash
# Check enabled APIs
gcloud services list --enabled --filter="name:(bigquery OR aiplatform OR pubsub OR iamcredentials)" --project="${PROJECT_ID}"

# Check BigQuery Connection
bq show --connection "${PROJECT_ID}.${BQ_LOCATION}.continuous-query-vertex-ai-connection"

# Check Service Account IAM policy
gcloud projects get-iam-policy "${PROJECT_ID}" \
    --flatten="bindings[].members" \
    --format="table(bindings.role)" \
    --filter="bindings.members:bq-continuous-query-sa"
```
